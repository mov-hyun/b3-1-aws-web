# 계정 보안과 과제용 IAM

## 확인한 상태

- 무료 플랜, USD 100 크레딧, 서울 리전 선택 확인.
- 2026-10-19 루트 계정에 `movhyun-root-mfa` 패스키 MFA 등록 확인.
- 루트 액세스 키는 콘솔에서 0개임을 확인.
- AWS에서 고객 관리형 정책 `B31LabEC2Seoul`, `B31LabOwnMFA` 생성 성공을 확인했습니다.
- `b3-1-lab`의 최초 비밀번호 변경 후 서울 콘솔 홈 로그인을 확인했습니다.
- 초기 과제용 패스키 등록 표시 후 재로그인에서 사용할 인증수단을 사용자가 확인하지 못해 복구를 진행했습니다. 등록 표시와 실제 재로그인 검증을 구분합니다.
- 루트 콘솔 재로그인을 확인했습니다. `b3-1-lab` 상세 화면에서 연결 정책 3개(`B31LabEC2Seoul`, `B31LabOwnMFA`, `IAMUserChangePassword`)를 확인했고, 관리자 정책은 연결되어 있지 않습니다. 보안 자격 증명 상세 화면의 액세스 키는 0개입니다.
- 사용자가 직접 인증 앱 `b3-1-lab-app`을 등록하고 기존 과제용 패스키를 삭제했습니다. 인증 앱 1개 유지와 인증 앱 코드 재로그인 성공을 확인했습니다. 같은 MFA 세션에서 서울 EC2/VPC 조회·네트워크 생성·EC2 생성까지 성공했습니다.

## 과제용 계정 구성

사용자 이름: `b3-1-lab`.

연결된 고객 관리형 정책:

1. `B31LabEC2Seoul`: `infra/iam-policy.json`
2. `B31LabOwnMFA`: `infra/iam-self-mfa-policy.json`

자동 생성 임시 비밀번호를 첫 로그인에서 변경하도록 선택했고, AWS의 `IAMUserChangePassword` 정책이 함께 연결된 것을 확인했습니다. 이것도 자신의 비밀번호 변경 권한이며 관리자 권한은 아닙니다.

첫 정책은 MFA로 인증한 세션에서 서울의 EC2/VPC 조회와 필요한 생성·연결·수정·삭제 작업만 허용합니다. EC2는 `t3.micro`, IMDSv2 필수, 암호화된 gp3 10 GiB 이하로 제한합니다. 생성된 자원의 조작·정리는 `Project=b3-1` 태그가 있어야 합니다. 새 자원을 만들 때 반드시 같은 태그를 넣습니다. 생성 권한 자체는 자원 개수의 상한이나 전체 지출 한도를 강제하지 않으므로 한 대만 생성했는지 별도로 확인합니다.

두 번째 정책은 자신의 비밀번호와 MFA 등록에 필요한 작업만 허용합니다. 다른 사용자·정책을 생성하거나 권한을 확대할 수 없습니다. S3/RDS 권한, `AdministratorAccess`, `AmazonEC2FullAccess`, `iam:PassRole`은 부여하지 않습니다. 콘솔에 필요하지 않은 장기 액세스 키도 만들지 않습니다.

## 사용자가 직접 수행할 단계

- 루트와 과제용 사용자의 패스키·인증 앱 등록.
- 과제용 콘솔 비밀번호 입력과 최초 로그인.
- 로그인 시 요구되는 패스키·MFA 인증.

루트는 초기 계정 보안과 과제용 IAM 준비에만 사용합니다. VPC·EC2 실습은 `b3-1-lab`으로 로그인한 뒤 수행합니다.

## 최초 로그인 후 사용자 MFA

1. 콘솔 오른쪽 위의 사용자 이름이 `b3-1-lab`인지 확인합니다.
2. 사용자 메뉴의 보안 자격 증명에서 MFA 등록을 시작합니다.
3. 사용할 휴대폰 인증 앱을 준비하고, 디바이스 이름은 `b3-1-lab-app`으로 지정합니다. 이 이름은 본인 사용자 이름으로 시작해야 정책의 범위에 맞습니다.
4. `인증 관리자 앱`을 선택합니다. 사용자가 직접 QR 코드를 스캔하고, 현재 6자리 코드와 다음에 바뀐 6자리 코드를 차례로 입력해 등록합니다. QR·비밀키·인증 코드는 저장소와 채팅에 남기지 않습니다.
5. 등록 성공을 확인한 다음 MFA를 사용해 다시 로그인합니다. 인증수단 선택 화면이 표시되면 새로 등록한 인증 앱 방식을 고릅니다. 로그인과 서울 EC2 조회가 성공해야 사용 가능한 설정으로 확인합니다.

복구는 루트의 IAM 사용자 상세 화면에서 인증 앱을 추가한 뒤 기존 과제용 패스키를 삭제하는 방식으로 진행했습니다. 두 인증수단 변경의 최종 단계는 사용자가 직접 수행했습니다. 루트에서 로그아웃한 뒤 과제용 사용자의 인증 앱 로그인 화면을 준비했습니다.

정책 때문에 EC2 작업이 거부되면 관리자 권한을 추가하기 전에 로그인 사용자·MFA 세션·서울 리전·자원 태그·요청 조건을 순서대로 확인합니다.

## 보안 자격 증명 화면의 조회 오류

2026-10-19 패스키 등록 후 `Passkey MFA device assigned`, MFA `(1)`과 함께 `iam:GetMFADevice` 액세스 거부가 표시되었습니다. 앞의 두 표시는 등록 성공 근거이며, 액세스 거부는 패스키 상세 인증 정보 조회에 대한 것입니다. `iam:GetLoginProfile`, `iam:ListAccessKeys`, `iam:ListSigningCertificates` 조회도 허용하지 않아 해당 패널에 오류가 표시됩니다. 현재 정책에 없는 조회 작업이며, 이 화면만으로 MFA 등록 실패를 판단하지 않습니다. 실제 로그인용 인증수단과 서울 EC2 조회를 별도로 검증합니다. 최종적으로 인증 앱 MFA 로그인과 EC2/VPC 생성까지 성공했습니다.
